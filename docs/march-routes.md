# 进军箭头（march）：这 111 条到底是什么

> 写给三个月后没有上下文的我。
> 起因：Rick 问「你说进军箭头 5:111 是什么意思？」——那是最初基线。
> 2026-07-23 完成第五轮高置信复核后，当前为 15:111；另有 1 个 `founding` 事件带建国前军事阶段，总计 16 个实体、20 个路线分段。

## 一句话

**111 是「军事类事件」的总数，当前其中 15 条实体已有进军箭头（最初为 5 条）。**
此外「唐朝建立」分类为开国而非军事，但正文明确包含 617 年晋阳起兵至入长安的军事前置阶段，因此总 march 实体数是 16。
但 111 **不是交付目标**——它是候选池。真正该画箭头的远少于 111，见下文。

---

## 这是 Rick 要的哪件事

Rick 的原话（第 4 点，他明确要求「单独立一个专项」）：

> 当选中某一个事件，我们去表达它在地图上的位置的时候，现在的表达是不太精确的……
> 比如说某件事情如果发生在特定的某个城市，那就应该是地图上的一个点；
> **如果是某个军队在往某个方向进攻，那它应该是一个箭头**，或者是像那种军事地形图上的标注一样。

「点」那半边已经做完了：选中事件 → 地图上落一个印章标注（族色作底、印章字形作芯）。
**「箭头」这半边机制已成，但内容仍稀疏**——这就是最初 5:111 的含义。

## 关键：111 里有多少真该画箭头

**盲目铺到 111 会把箭头变成装饰。** schema 里写死的约定就是防这个：

> 只填史载明确的起讫，无可考者留空 —— **没有数据而画箭头即是编造方向**。
> （`schema/event.yaml:62-65`）

按事件形态分，剩下 96 条大致是三类：

**A. 有清晰的单向进军 —— 该画，也画得出**
靖康之变（金军两路南下）、山海关之战（清军入关）、隋灭陈（贺若弼/韩擒虎渡江）、
石敬瑭借契丹灭后唐（契丹自扬武谷南下晋阳）、崖山海战（潮阳港入海至崖山的最后一程）之属。
这类是箭头的正主。

**B. 多阶段拉锯战 —— 画一根箭头反而失真**
安史之乱（755-763，八年，范阳起兵→洛阳→长安→睢阳→收复两京，来回拉锯）、
太平天国（1851-1864，十四年，金田→永安→武昌→南京→北伐/西征）、
楚汉战争（-206~-202）、抗日战争（1937-1945）之属。
这类要么拆成多段 march（一段一阶段），要么根本不该用箭头表达——
它需要的是**时间轴上的多个事件**，而不是地图上的一根线。

**C. 没有进军可言 —— 不该画**
三家分晋（-403，是政治事件）、大泽乡起义（起兵点即事发地）、
辛亥革命（武昌首义后是各省响应，不是进军）之属。

**所以合理的目标不是 111，是「A 类全部 + B 类拆段 + C 类明确留空」。**
我现在给不出 A/B/C 的准确条数——那需要逐条读史料判定，正是这个专项的工作本身。

## 数据支撑：能画的画得了吗

| 检查项 | 实测 |
|---|---|
| 96 条待办中，**事件落点（`location`）有坐标** | **78 条** |
| 无 `location`（连落点都没有） | 18 条 |
| 可作为 march 端点的地点总数 | **1359 个**（全带坐标） |

抽查典型进军起点，地点库基本够用：
幽州（范阳节度使治所）✓ / 长安 ✓ / 汴梁 ✓ / 建康 ✓ / 寿春 ✓ / 金田 ✓ / 山海关 ✓ / 盛京 ✓ / 北平 ✓

**但查地名要按古名查，别按今名。** 实测「开封」查不到 `name=开封` 的实体，
它在库里是 `pl_kaifeng`（`name: 汴梁`，`aliases: [汴州, 大梁, 开封府, 东京]`）；
而「开封」作为 `modern_name` 同时挂在三个实体上——`pl_xiangfu_shi`（祥符）、
`pl_tongqu`（通济渠）、`pl_kaifeng`（汴梁）。这正是 WORKLOG 里悬而未决的
「地名历时性该合还是该分」议题的又一例。写 march 时按古名找 id，找不到再查 aliases。

**结论：总量上的地点地基够，但历史同名实体不能跨时代借用；卡点是史料判定与缺少少数关键中继点。**

## 一段 march 长什么样

数据格式（`schema/event.yaml` / `schema/battle.yaml` 同构）：

```yaml
march:
  - from: pl_jiangling      # Place ref，必须带坐标
    to: pl_chibi            # Place ref
    note: 曹操取江陵后顺江东下,与孙刘联军遇于赤壁。《三国志·武帝纪》
```

- `from`/`to` 都是 Place 引用，**不是自由文本**——它们受 `validate_data.py` 的
  march 合同约束；坏结构、悬空端点、非 Place 端点分别触发
  `E_MARCH_STRUCTURE` / `E_DANGLING_REF` / `E_REF_TYPE`。
- `note` 里要带**史料出处**。当前 20 个分段全部带出处，这是数据约束的一部分。
- 多段就写多条，顺序即进军顺序（见明北伐：应天→汴梁→大都）。

渲染在 `frontend/src/components/map/MapPanel.vue` 的 `paintMarch()`：
画 `march-line` + `march-casing` 两层线 + 端点箭头 Marker。
**无 march 则不画**——代码注释写着「没有数据而画方向即是编造」。

## 已知的坑

- **`paintEventMark` 与 `paintMarch` 的清理必须分开**。曾经 `paintEventMark` 内部
  连 march 图层一并清，于是「先画箭头后画印章」时印章把箭头擦掉了——
  现象是印章在、箭头恒为 0。已修（`clearEventMark` / `clearMarch` 分离）。
- **目测不算证据**。曾据小图称箭头方位角错，用变换矩阵反解尖端向量后夹角 0°——
  是我看岔了。验箭头方向要算，不要看。
- **地图验证一律用 Playwright**，in-app Browser pane 里 maplibre 渲染不起来
  （`isStyleLoaded` 恒 false）。
