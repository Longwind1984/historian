§0执行摘要

history-kb 的数据地基与三视图骨架（时间柱 / 地图 / 谱系星图）已经成型，视觉语言（纸墨 × 印章 × 古籍）辨识度高。当前最伤体验的不是缺功能，而是一批已交付交互的断点与半闭环：主 CTA 按钮点击即抛错、三处「地图定位」是无反馈空操作、URL 年份分享恢复失效、搜索选中后时间柱原地不动。

刷年 → lens → 右栏同步闭环① 健康 点选实体 → 三视图联动闭环② 多处断裂 ← 本 PRD 主修

§1背景与方法

1.1 产品现状

互动中国历史知识库：前 2100（大禹）→ 2026，7,442 实体 / 10,095 关系，YAML 为唯一真相源。前端 Vue 3 + Pinia + Vite，MapLibre GL（疆域地图）+ d3-force Canvas（图谱 2D）+ 自研 Three.js 引擎（星云 / 时空柱）。主界面两条核心闭环：

  • 闭环① · 刷年：滚动时间柱 → 顶部 lens 线 → 右栏年号读数 / 疆域地图 / 「此刻在世」列表同步（经 year / settledYear 双年份防抖）。此闭环机制健康，是本产品最独特的交互资产。
  • 闭环② · 点选实体：时间柱 / 地图 / 图谱 / 星点选 → 档案面板 + 各视图高亮联动 + URL hash 同步。本 PRD 的问题清单主要集中在这一环。

1.2 方法

  • 对 frontend/src 全部 13 个 Vue 组件、5 个 Pinia store、16 个星图引擎模块做逐文件走查；P0 级断点均由本人二次打开源码核实（非仅凭记忆或日志）。
  • 交叉引用 handoff.json（2026-07-17 实测版）的 known_defects 与 open_questions、docs/roadmap-v2.md 的 M4 规划，避免与已规划工作重复造轮子。
  • 每条问题标注证据（文件:行号）；每条方案给出验收标准，可直接转成 E2E 用例。

1.3 非目标

  • 不新增数据内容、不改后端 API 契约（B/C 批若需新端点会单独标注，均可用现有端点实现）。
  • 不重复 roadmap 已立项的新玩法（事件长河 T4.8、进军箭头内容工程 march-A 类）——本 PRD 只覆盖「已有界面的交互质量」。
  • 不做视觉重设计：现有纸墨语言保留，方案全部在其体系内延伸。

2.3 已存在的良好设计（保留并延伸）

  • 四态时间锚：生卒确凿 / 存疑渐隐斜体 / 仅卒年 / 仅在位 —— 「不确定的不伪装成确定的」，本 PRD 所有方案遵守同一伦理。
  • 双年份防抖（year / settledYear 180ms）：重活不落每帧，是刷年流畅的根。
  • hover 预览 + 350ms 抑制窗：扫读不锁屏，点击才锁定。
  • 朝代色板跨视图一致（星云/时空柱/时间柱同源 palettes.js）。
  • 时空柱扫描环 ⇄ 时间柱双向刷年（带防环路 guard）——B 批联动方案照此模式。

§4设计原则

从项目已有气质中提炼，作为 §5 所有方案的裁决标准；新交互与旧交互冲突时，按此顺序取舍。

原则含义在本 PRD 中的应用
1 · 界面不撒谎延伸「四态时间锚」伦理：按钮点了必须有反应，注释声称的行为必须存在，做不到的就从界面上拿掉。A 批全部；删死按钮优于留摆设
2 · 一年一世界lens 线是全站锚点：任何「选中实体」若带时间属性，都应能把用户带回它的年代。B1 搜索联动滚动；A2 定位含跳年
3 · 三视图一体选中、年份、配色是全局事实，任何视图不得私有化（底图双源即反例）。A5 统一底图；B2 星云响应外部选中
4 · 键盘可达研究工具的高频路径（刷年、搜索、切视图）必须可纯键盘完成，且键位全站一张表。C1 键盘体系
5 · 繁简有据品牌层从繁（紀年圖譜），数据层从史（人名地名依数据源），UI 层从简（按钮、提示、空态）。D1 文案规范
6 · 宁缺毋滥数据缺失时显式说「待补」，不编造、不硬画（沿用 march 红线：没有数据而画箭头即是编造方向）。D4 年谱、D5 地图标注的缺失态
