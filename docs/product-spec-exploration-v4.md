# v4「探索」产品规格

> 状态：**总体方向与原型已批准；首个生产切片已进入 `frontend/` / `backend/`，真实 LLM 编织与持久化仍未接入**
> 日期：2026-07-27
> 适用版本：以 v1.3.0 静态历史工作台为基线
> 本轮交付：产品判断、信息架构、交互状态、数据边界、验收口径、视觉原型与开发标注

## 一句话定义

把「纪年图谱」从一张预先编好的静态历史图，升级为一台**由问题或书籍驱动、能临时编织证据化历史网络的时空探索装置**。

用户不是向聊天机器人索取一段答案，而是在提出问题、确认边界之后，获得一条可以播放、拆解、质疑、回溯出处并继续扩展的历史脉络。

---

## 1. 为什么要做

现有工作台擅长回答：

- 某一年有哪些人物、政权和事件；
- 某个实体与谁存在已录入关系；
- 某个历史条目发生在哪里；
- 一段已经结构化的历史如何沿时间与地图播放。

它不擅长回答：

- 一件事为什么发生，哪些条件只是背景、哪些构成直接触发；
- 同一批人物的立场、策略和关系如何随事件推进而变化；
- 一个历史判断来自事实、作者解释还是后人的争论；
- 用户指定的一本书如何被拆成事件、因果、人物、论点和证据；
- 当前静态库尚未录入的细节如何临时进入图面，又不污染既有事实库。

根本矛盾不是「缺一个聊天框」，而是现有数据模型主要承载**实体与静态关系**，无法承载一次探索过程中逐步形成的**研究范围、叙事主线、论点、证据、争议与版本**。

---

## 2. 产品判断

### 2.1 核心判断

1. **问题本身是一等对象。**
   用户的原始问题、确认后的时空范围、观察尺度与叙事主线必须被保存；LLM 不能直接跳到长答案。

2. **叙事必须落成可检查的结构。**
   一次探索的结果不是聊天记录，而是由事件、人物、地点、论点、证据和有方向的关系组成的「探索网络」。

3. **静态知识库是底座，不是容器上限。**
   新生成内容先进入独立的探索层；只有人工复核后，才可能晋升为正式知识库内容。

4. **作者视角不能被中和。**
   书籍模式必须同时保留「作者如何看」和「可核查的事实材料」，不能把作者的论证改写成无主体的百科共识。

5. **反方视角不是强制凑平衡。**
   只有找到可追溯的学术意见或史料冲突时才展示；找不到时明确写「尚未补充反方材料」，不由模型虚构反驳。

6. **地图只展示有依据的地点。**
   延续现有「可定位才播放」原则；模型不得从籍贯、出生地或模糊地名猜测事件坐标。

7. **LLM 是研究编辑，不是历史权威。**
   它负责框定、拆解、提议、链接和质检；证据等级与不确定性始终对用户可见。

8. **书籍探索是唯一工作空间，编织与播放是其中的动作。**
   用户不需要先理解三种产品模式：研究约定收进书籍页，论证链直接呈现编织结果，Scene 播放控制按需展开在地图内，完整事件顺序由左栏时间·事件柱承接。所有动作共享一个 Exploration revision，不能换题、重置 Scene、丢失段落或把旧地点伪装成当前地点。

### 2.2 否决的简单方案

| 方案 | 否决原因 |
|---|---|
| 在现有右栏加聊天框 | 会把地图、时间轴和图谱降为回答的插图，无法形成可复用的探索对象 |
| 直接把模型回答写回 YAML | 混淆已审定事实与临时生成内容，破坏当前数据可信度 |
| 只输出一篇长文或报告 | 阅读顺畅，但丢失时空联动、因果分叉、人物关系和证据定位 |
| 自动给所有观点配一个反方 | 容易制造虚假对称；没有真实材料时，宁可暴露证据缺口 |
| 一次性生成完整巨图 | 慢、不可控、难校验；规模随内容线性增长，且用户不知道从哪里读起 |

## 3. 用户与首批任务

### 3.1 问题驱动

用户对某个历史阶段、事件或人物网络感兴趣，但尚未形成准确研究问题。

示例：

> 我想理解明初靖难之役是怎样一步步发生的。

系统应先确认：

- 时间：默认 1398–1402，可继续向前补削藩背景；
- 空间：北平—华北—运河—南京；
- 观察尺度：关键决策与军事进程，不展开所有战斗；
- 主线：建文削藩、燕军南下、帝位更替；
- 需要的解释层：事实脉络、权力结构、史家解释。

确认后才开始编织。

### 3.2 书籍驱动

用户已经选择一本具体著作，希望在忠实保留作者论证的前提下，看清它描述的历史网络。

示例：

> 导入《安史之乱：历史、宣传与神话》，从河北边镇结构、两京攻防到后世历史记忆，梳理战争如何跨地域展开。

系统应先确认：

- 处理整本书还是选定章节；
- 书籍版本、页码体系和文本完整度；
- 作者研究的时间范围与用户此次关注范围；
- 只梳理作者论证，还是同时补充外部材料；
- 外部材料的边界：现有知识库、用户另行提供的材料、公开史料或学术研究。

## 4. 信息架构

主导航增加第三个一级模块：

```text
时间柱    谱系星图    探索
```

「探索」内部不是两个孤立工具，也不再分成「编织 / 播放 / 书籍」三个顶层模式。入口以历史问题为主构图，上传本地书籍是紧邻主动作的显式分支；两者汇入同一个书籍探索工作台：

```text
历史问题 ─┐
          ├─ 书籍探索工作台
私人书籍 ─┘   ├─ 正文 / 锚点 / 时间·事件柱 / 网页来源
              ├─ 研究约定与论证链（编织）
              ├─ 地图与按需 Scene 播放
              └─ 关系化证据 / 继续追问
```

### 4.1 探索入口

一级「探索」先进入统一的探索入口。首屏只有一个主要问题输入区：**提出历史问题**是主路径；**上传本地书籍**作为与主 CTA 并列、始终可见的次级动作，点击后打开专用上传弹层。支持格式只在按钮旁和弹层副标题中出现，不把上传藏进 `+`，也不再用第二张等权卡片把产品切成两个互不相干的工具。

已有探索以一行“继续当前探索”放在主输入区之前；示例探索放在其后。前者不会替代空状态，后者不会冒充用户当前书籍。模型设置、统计数字和功能说明不占首屏。

### 4.2 单一书籍探索工作台

工作台采用一套可调宽度的三栏骨架：左栏是阅读、锚点、来源与纵向事件导航，中央是论证结构和地图，右栏是关系化证据与继续追问。左右两条分栏与中央 Brief / 论证 / 地图两条横向边界都支持拖动、键盘调整、比例记忆与双击复位；地图保留最小可用高度。用户调整的是阅读视野，不是数据状态。其内部由三个始终同步的层次组成：

1. **研究约定**：原问题、范围、主线、来源范围；
2. **时空叙事**：地图、时间、人物状态与因果推进；
3. **证据透镜**：事实、作者判断、模型推断、争议与反方材料。

对话是修改研究约定和继续追问的入口，不是长期占据视觉中心的内容流。右栏输入采用 `+ / 输入 / 发送` 的一体式 composer：`+` 负责附加摘录、外部材料或人物事件，输入框负责提出当前书籍问题，不在上方重复解释“可以提问”。编织没有独立页面；它的可见结果就是中央论证链。播放也没有独立页面；默认只在地图内保留一个次级入口，主动展开后才出现 Scene 步进、变速与进度，关闭后不占据工作台高度。完整时间顺序始终可以从左栏「时间 · 事件柱」查看。

## 5. 核心体验

### 5.1 问题模式

#### 阶段 A：表达

用户用自然语言说出兴趣，不要求先会写研究题目。

系统只做一轮高价值澄清，优先给可点选的范围建议；不以连续盘问阻断用户。

#### 阶段 B：范围确认

系统返回一份可编辑的「研究约定」：

- 核心问题；
- 起止时间与地理范围；
- 主体人物/组织；
- 2–4 条叙事主线；
- 默认来源与解释层；
- 明确不包含的内容。

用户点击「开始编织」后，约定成为本次探索的基线版本。

#### 阶段 C：渐进编织

先生成 6–12 个骨架节点，而不是等待完整巨图：

1. 关键背景；
2. 直接触发；
3. 转折；
4. 结果；
5. 长期影响；
6. 已知争议。

每个节点完成后立即可见。证据未就绪的节点显示为「待核」，不装作完成。

#### 阶段 D：探索与播放

播放一个「场景」时，同时更新：

- 当前时间与时间轴锚点；
- 地图焦点、路线或地点；
- 场景中的关键人物及其当时立场；
- 前因、直接结果与后续影响；
- 浮窗中的摘要、来源和不确定性；
- 证据透镜中的作者/史料/反方视角。

用户手动拖动地图、时间轴或切换节点时，自动暂停播放但保留当前场景。

#### 阶段 E：继续追问

追问必须作用于当前结构，例如：

- 展开一个节点；
- 改换观察尺度；
- 比较两位人物的决策；
- 只看军事路线；
- 检查某条因果关系的证据；
- 把一个争议拆成多个观点。

它不应只在聊天末尾追加一段孤立回答。

### 5.2 书籍模式

#### 阶段 A：私人导入

首版推荐：

- 支持 TXT、Markdown、EPUB 的可解析文本；
- PDF 仅接收已有文本层的文件，扫描 OCR 后置；
- 文件默认只在当前浏览器会话/本地工作区可见；
- 未经用户明确操作，不发布原文、全文索引或探索结果。

#### 阶段 B：版本与章节确认

系统读取书名、作者、版本、目录与页码锚点，让用户选择整书或章节范围。解析失败处必须暴露，不静默跳过。

#### 阶段 C：作者论证拆解

系统分别提取：

- 作者明确陈述的事实；
- 作者引用的材料；
- 作者自己的判断；
- 作者使用的因果关系；
- 作者没有明说、但模型推断出的结构。

前四者和第五者必须使用不同证据状态；模型推断不能伪装成作者原意。

#### 阶段 D：外部核对

对重要论点按需补充：

- 可互证的原始材料；
- 其他研究者的不同解释；
- 史料冲突；
- 尚无法核对的缺口。

外部材料与原书材料分层保存，不能混成一个来源列表。

#### 阶段 E：从书进入时空装置

用户点击任一论点、事件或人物，中央结构和时间/地图同步定位；点击出处可回到原文页码或段落。

## 6. 关键对象

### 6.1 探索对象

| 对象 | 含义 |
|---|---|
| Exploration | 一次可保存、可继续的探索 |
| Brief | 经用户确认的问题、范围、尺度与主线 |
| Corpus | 本次允许使用的知识库、书籍与外部来源集合 |
| Thread | 一条叙事主线，如「建文削藩」 |
| Scene | 可播放的最小叙事单元，绑定时间、地点、人物与证据 |
| Claim | 关于事实、因果或解释的可检验陈述 |
| Evidence | 支持或反驳 Claim 的具体出处与原文定位 |
| Perspective | 某位作者、史家或材料提供者的观察角度 |
| Exploration Node | 探索层中的人物、事件、地点、组织、概念或论点 |
| Exploration Edge | 时序、参与、因果、影响、支持、反驳或解释关系 |

### 6.2 证据状态

所有节点和边都必须属于以下一种，不以模糊的百分比分数替代：

| 状态 | 展示语义 |
|---|---|
| 史料直述 | 可定位到原始材料的明确陈述 |
| 多源互证 | 两个或以上独立来源支持 |
| 单一来源 | 目前只有一个可定位来源 |
| 作者判断 | 明确属于指定作者的解释 |
| 模型推断 | 系统从材料中提出，尚待用户确认 |
| 存在争议 | 有真实、可定位的相反材料或解释 |
| 证据缺口 | 当前无法支持，不能作为事实播放 |

### 6.3 关系语义

首版只支持对用户有解释价值的关系：

- `发生在 / 参与 / 隶属 / 同期`
- `触发 / 促成 / 阻碍 / 导致 / 回应`
- `支持该判断 / 反驳该判断`
- `作者解释为 / 模型推断为`

「因果」不能从事件先后自动生成。系统只能提议，证据不足时保留为模型推断。

## 7. 静态库与探索层的边界

```text
已审定知识库（只读底座）
        │ 检索 / 引用
        ▼
探索层（会话级、可版本化）
        │ 人工复核 + 数据校验
        ▼
候选晋升集（默认不自动执行）
        │ Rick 明确批准
        ▼
正式 YAML / GeoJSON
```

硬规则：

- LLM 不直接修改正式 YAML；
- 探索层允许同名临时实体，但应尝试链接到正式实体 ID；
- 链接不确定时保留候选，不强行合并；
- 晋升必须包含来源、证据定位、实体去重与引用迁移检查；
- 书籍中的作者判断默认不晋升为正式事实。

## 8. LLM 工作方式

以下是一次编织的逻辑步骤，不要求首版实现成多个 agent 或服务：

1. **范围编辑**：把用户兴趣改写成可确认的 Brief；
2. **来源规划**：列出将使用和明确不使用的材料；
3. **骨架提取**：先形成少量关键 Scene 与 Thread；
4. **证据链接**：为每个 Claim 绑定来源与定位；
5. **结构提议**：提出因果、影响与人物互动关系；
6. **反证检查**：检查冲突、不同解释和证据缺口；
7. **引用审计**：阻止没有来源的内容以事实状态进入播放。

生成时的用户可见状态：

```text
正在确定范围 → 正在建立骨架 → 正在链接出处 → 正在检查争议 → 可探索
```

不显示模型内部思维链；只显示可验证的计划、来源和结果。

## 9. 视觉方向如何收敛

原来的三种视觉方向提供了三组有价值的部件，但把它们做成顶层模式会要求用户先判断「我现在该编织、播放还是阅读」。2026-07-26 的最新收敛是：**只保留史料工作坊这一套页面骨架**。

```text
书籍探索工作台
  ├─ 顶：全局导航 + 书籍工作栏（仅两行）
  ├─ 左：正文、锚点、时间·事件柱、网页来源
  ├─ 中上：研究约定与论证链（吸收编织能力）
  ├─ 中下：地图、Scene 浮窗、按需播放（吸收播放能力）
  └─ 右：作者视角、材料关系、证据缺口与继续追问
```

原「编织态」保留的不是入口，而是研究 Brief、论证链、待核关系与局部重编织；原「播放态」保留的不是页面或常驻 dock，而是地图中的次级 Scene 播放入口。页面布局始终稳定，阅读、理解、观看过程不再互相打断。

连续阅读是第一动作。左栏默认打开正文，提供正文 / 锚点二级切换；段落边缘的锚点既能进入结构，也能被逻辑节点的“回到原文”反向定位。左栏的「时间 · 事件柱」与中央地图使用同一份 `sceneIndex`，只提供纵向阅读方式，不复制另一套时间状态。

被否决的方案：

- 保留三态入口但默认书籍态：仍把内部实现概念暴露给用户；
- 隐藏另外两态但保留不可达组件：形成两套状态与维护负担；
- 播放时整体切换成另一套导演台：地图更大，但会让原文与证据失去同屏参照。

## 10. 首版范围

### 当前已实现的生产切片

- `探索` 一级路由与真空入口：历史 Prompt、TXT / Markdown / EPUB 与衍生示例可独立开始；
- 桌面可调三栏，移动端阅读 / 时空 / 出处三视图；
- Prompt 会建立可编辑范围合同和来源缺口脚手架，不生成历史结论；
- TXT / Markdown / EPUB 私人导入、章节与段落 locator、无伪页码；
- EPUB 安全容器解析、spine 阅读顺序、按章渲染与串行 revision 阅读进度；
- 微信读书顶层打开、Chrome Side Panel 主动选区桥和手动位置/摘录兜底；
- 后端有界进程内会话、6 小时失效、revision 乐观并发与显式删除；
- 论证节点展开、返回示范正文锚点；导入文本保持“尚未建立关系”；
- MapLibre Scene 地点、浮窗、无地点清理与地图内次级播放；
- 有坐标来源的材料地点用独立 GeoJSON source / 连续 Bézier `LineString` 表达，不使用直虚线、箭头或地点串联；
- full profile 当前以已有 `mp05d1`（1908）配准瓦片作历史地理参考并明确标注「非当前疆界」；safe profile 在构建期不注册或请求该 source；
- 右栏 composer 可把问题绑定当前段落并记录为 `recorded_no_llm`；
- 私人文本不写入仓库、日志或数据库，进程重启即清除。

当前明确未实现：真实 LLM 编织、持久化恢复、EPUB CFI 与版本/页码绑定、PDF / OCR、微信读书自动读取或官方进度同步、外部材料检索、探索包导入导出和正式库晋升。

### P0：问题探索闭环

- 新增「探索」一级入口；
- 自然语言问题输入；
- 一轮范围确认与可编辑 Brief；
- 基于现有知识库的检索；
- 渐进生成 6–12 个骨架节点；
- 时间、地图、人物、因果与证据联动；
- 场景播放、暂停、上一步、下一步；
- 节点/关系一跳查看来源；
- 探索层与正式库隔离；
- 浏览器本地保存和导出探索。

### P1：书籍探索闭环

- TXT / Markdown / EPUB 私人导入；
- 章节与页码锚定；
- 事实、作者判断、模型推断分层；
- 作者材料与外部材料分层；
- 重要论点的反方材料；
- 从论点跳转到原文、时间和地图；
- 继续拆解、调整范围、重新编织。

### P2：后续能力

- PDF OCR；
- 登录与跨设备私人工作区；
- 多本书对读；
- 协作批注；
- 可分享的只读探索；
- 复核后晋升正式知识库；
- 研究者自定义来源连接器。

### 明确不在首版

- 自动生成整部中国史；
- 无限制全网检索；
- 自动发布导入书籍或长篇原文；
- 多人实时协作；
- 模型自动改正式数据；
- 手机端完成复杂导入与编织。

移动端首版只承担查看、播放、切换场景与检查出处；复杂范围编辑和书籍导入以桌面端为主。

## 11. 隐私、版权与外部材料

### 11.1 书籍默认私有

第一阶段建议采用本地优先：

- 原始文件保留在浏览器本地；
- 解析后的索引保留在 IndexedDB 或可导出的本地探索包；
- 只有完成当前模型任务所需的片段才发送给模型；
- 发送前在界面明确显示「本次将使用哪些章节」；
- 服务端不默认持久化全文。

这条路线牺牲跨设备同步，但与当前无账户、公开站点的产品形态更匹配，也降低私人文本和版权材料的外溢风险。

### 11.2 引文克制

- 图面只显示完成判断所需的短引文；
- 大段原文回到用户自己的本地阅读区；
- 分享探索时默认只含摘要、短引文与出处，不携带整本书；
- 书籍版本与页码定位必须保留，避免无法复核。

### 11.3 外部检索

- 明确显示本轮查询了哪些来源；
- 外部请求必须有超时和失败状态；
- 同一来源失败后不循环重试；
- 未获得材料时标记「待补证」，不让模型补写。

## 12. 性能与成本边界

探索不能靠一次全量生成：

- 初始骨架限制为 6–12 个 Scene；
- 初始可见网络建议不超过 20 个节点、30 条关系；
- 展开一个节点时按需检索和生成，成本随用户实际探索增长；
- 地图、星图和书籍解析模块继续按需加载；
- 结构更新只重算受影响子图，不重建整个现有 7,396 实体网络；
- 长书先建章节索引，再按选定范围处理，不在导入时全书逐段调用模型；
- 可中止、可恢复；失败保留已完成骨架与引用。

首版必须能显示本次模型调用的阶段、可取消状态和近似成本；具体模型、价格与限额在技术设计阶段按实际提供方查询后确定。

## 13. 验收口径

### 13.1 产品完成

以「靖难之役」为验收题，用户能够：

1. 从一句模糊兴趣得到并编辑研究范围；
2. 在确认后看到首批历史骨架逐步出现；
3. 播放至少 6 个时空场景；
4. 在同一场景看见时间、地图、人物状态和因果关系同步；
5. 一次操作内看到任一事实节点的出处；
6. 明确区分史实、作者判断、模型推断和争议；
7. 修改主线后得到局部重编织，而不是整场清空重来；
8. 保存并重新打开这次探索；
9. 全程不修改正式知识库。

以一本用户导入书籍为验收材料，用户能够：

1. 选择章节并确认版本/页码体系；
2. 从作者原文跳到结构化论点，再跳回原文；
3. 看见作者判断与模型推断的边界；
4. 为重要论点查看支撑材料与真实反方材料；
5. 外部材料缺失时看到缺口，而不是伪造的平衡意见；
6. 导出的探索不包含未经选择的长篇原文。

### 13.2 质量闸门

- 事实态节点的来源覆盖率 100%；
- 作者判断必须绑定作者与原文定位；
- 模型推断必须可被用户接受、驳回或改写；
- 因果边不得仅由时间先后自动产生；
- 无坐标依据的场景不上地图；
- 取消/失败后已完成结构可恢复；
- 键盘可完成主要浏览与播放；
- 澄/夜主题都不出现对比度、遮挡和布局断裂；
- 初始工作台不因导入地图/3D/整书处理而阻塞。

- 产品构建默认不带旁注；内部评审构建可按 G/W/P/B 稳定 ID 定位内容。

- 常驻 Presenter Card、章节轨、发布会进度条或右侧讲稿；
- 通过聚光遮罩把未讲区域持续压暗；
- 把产品经理讲稿塞进 prototype 的中心舞台；
- 用一个全屏异常蒙层冒充不同区域的业务状态。

## 16. 观点关系：不强行制造正反

书籍工作台的地图播放与证据区共用「关系分类」，不使用固定的「正方 / 反方」栏位。

| 关系 | 含义 | 可见文案示例 |
|---|---|---|
| 互证 | 独立材料支持同一事实或机制 | 「从另一材料确认组织审查的存在」 |
| 补充 | 解释不同层面，彼此可以同时成立 | 「补充制度机制」「补充社会层面」 |
| 关注层级不同 | 一个讨论组织结构，另一个讨论个体经验 | 「观察尺度不同，未构成冲突」 |
| 方法差异 | 材料或方法不同，结论尚不能直接比较 | 「史料口径不同」 |
| 范围限制 | 后一材料只修正前一判断的适用范围 | 「结论只适用于 1942–1943」 |
| 直接冲突 | 对同一事实、因果或结论作出不可同时成立的判断 | 「对运动发起原因存在直接分歧」 |
| 证据缺口 | 当前只有主张，没有足够材料支持或反驳 | 「尚待补证」 |

硬规则：

- 同时出现不等于互相冲突；
- 讨论不同层级不等于立场对立；
- 不同措辞不等于不同结论；
- 只有作用于同一个 Claim、且命题不可同时为真时，才标「直接冲突」；
- 模型先提议关系，用户可以改；关系必须绑定各自来源；
- 没有冲突材料时，显示「当前未发现与该判断直接冲突的材料」，不生成占位反方。

## 17. 书籍阅读器与网页来源

### 17.1 推荐产品结构

书籍探索工作台不是左边读书、右边看图的松散拼接，而是一个可逆链路：

```text
原文选区
  → 作者观察 / 史实陈述
  → 事件、人物、地点与时间
  → 地图和论证网络
  → 任一节点回到原文
```

地图必须是书籍探索工作台的常驻核心区域：

- 约占中央工作区的三分之一；
- 只标注当前章节或当前选区能支持的地点；
- 选择原文时，地图定位相关地点；
- 选择地点时，反向高亮相关段落、事件与材料；
- 没有可靠地点时保留地图区域但显示「本段不具备可定位信息」，不从籍贯或现代常识猜点。

阅读器内部不是摘要卡片列表，而是两种可逆视图：

- **正文**：连续排版，段落边缘保留轻量锚点；选中段落只高亮当前段，不把正文拆成一堆卡片；
- **锚点**：按段落列出时间、论点、地点和关联 Scene；选中后同步中央结构与地图，并可立即返回正文；
- **结构回跳**：逻辑节点展开时展示对应摘录或作者论证摘要及其证据状态；“回到原文”必须滚动并聚焦绑定段落；
- **版本边界**：没有用户导入的确切版本时只能显示作者论证摘要与“版本待绑定”，不得生成伪原文或伪页码。

左栏另提供「时间 · 事件柱」一级 tab，复用中央 Scene 的同一状态；它解决窄栏里沿时间纵向浏览的问题，不复制一套事件清单或播放状态。

### 17.2 三种阅读接入

| 方案 | 能力 | 限制 | 首版决定 |
|---|---|---|---|
| 内置阅读器 | EPUB/TXT/Markdown 解析、章节、选区、页码锚点都可控 | 需自建解析与排版 | **P1 主路径** |
| 原站顶层页面 | 保留微信读书正常登录、阅读和原站能力 | history-kb 不能直接读取其 DOM/选区 | **微信读书阅读面** |
| Chrome Companion Extension | Side Panel 承载 history-kb，经用户主动操作桥接选区 | 需安装扩展；公开发布需固定 ID、权限披露与生产 origin 配置 | **本地 beta 已实现** |
| 跨站 iframe | 视觉上可能展示第三方页面 | 登录 Cookie / Storage 隔离，OAuth 顶层导航受限，父页不可验证登录 | **否决** |

2026-07-26 对微信读书公开阅读页的实测：

- 页面当前没有返回 `X-Frame-Options`；
- 公开 `Content-Security-Policy` 当前也没有 `frame-ancestors`；
- 这只说明页面**当前可能被展示**，不等于第三方登录 Cookie 一定可用；
- 即使 iframe 成功显示，浏览器同源策略仍禁止本站读取正文 DOM 和用户选区；
- 因此不能把微信读书 iframe 当作稳定的数据接口。

2026-07-28 又确认了一种独立失败态：微信端提示扫码登录成功，但跨站 iframe 仍停在“登录中”或未登录首页。前者只证明微信端授权完成，不证明第三方 iframe 取得了同一 Cookie / 存储上下文；父页面也不能跨域读取其登录结果。因此 `iframe load` 只能记为“尝试过”，不得晋升为“已登录”或“已连接”。

2026-07-28 进一步用同一真实 Chrome 复核：顶层 `weread.qq.com` 已登录，history-kb 内 iframe 仍停在登录态；控制台同时记录 OAuth 回调尝试导航顶层窗口被 sandbox 拒绝。放开顶层导航会把父站交给第三方页面控制，且仍不能保证共享第三方 Cookie / Storage，因此不作为修复。

现行方案：

1. 微信读书始终是 Chrome 顶层第一方页面，不再由 history-kb 尝试嵌入；
2. Chrome Side Panel 打开 history-kb companion 模式，窄栏默认展示「论证」，并可切换「时空 / 出处」；
3. 扩展只在用户点击「读取当前选区」时读取当前 URL、标题、定位与最多 2,000 字选区；
4. 读取后先本地预览；再次点击「加入当前探索」才向当前工作台发送；
5. 切换环境或收到终态回执必须清除选区正文与内存引用；回执不得回传正文；
6. 主站保留默认收起的手动位置 / 摘录同步，作为未安装扩展时的兜底；
7. 本地 beta 只连接 `127.0.0.1:5173`；线上入口在固定扩展 ID、精确 `VITE_WEREAD_COMPANION_ORIGIN`、生产 `frame-ancestors` 和隐私披露完成前不出现。

## 18. 地图高保真生产方案

视觉原型中的地图不能在生产环境里直接当一张背景图使用。那会造成标签不能避让、地点不能点选、时间不能联动，也可能把生成图中的错误地理信息固化。

### 18.1 生产分层

沿用现有 MapLibre，不新增第二套地图引擎：

```text
相机 / Scene 状态
  ├─ 历史栅格底图：现有「古」瓦片或经核验的替代底图
  ├─ 地形与水系：底图自带；必要时增加独立中性色参考层
  ├─ 历史地点：MapLibre symbol layer
  ├─ 行军 / 移动：line layer，必须有 geometry 与来源
  ├─ 影响 / 传播：独立 source / layer，不伪装成真实路线
  ├─ 材料关联：经过标签避让的柔性曲线，不使用箭头或直虚线
  ├─ 人物：绑定当时所在地点的 symbol
  ├─ 标签：原生碰撞避让与优先级
  └─ 图例 / 事件浮窗：可访问的 HTML 控件
```

### 18.2 视觉还原

- 底图使用真实栅格或矢量地图资产，不由 CSS 绘制假地图；
- 通过 MapLibre 的 `raster-saturation / contrast / brightness / opacity` 适配澄 / 夜；
- 中文标签使用可用的字形源或本地汉字字体回退；
- `text-variable-anchor`、`symbol-sort-key` 与 `text-allow-overlap:false` 负责避让；
- 重点地点使用稳定图标与文字，不用颜色作为唯一编码；
- 真实移动只在有来源的 geometry 上使用连续路线与方向语义；
- 材料关联禁止使用地点到地点的两点直连、箭头和机械等距虚线。原型默认从「当前材料 / Scene 浮窗」的中性 hub 向各地点独立发散：双层柔性 Bézier 曲线的外层定义关系走廊，内层给出连续性但不编码方向；曲线控制点绕开浮窗与地点标签。地点之间不互相串联，避免被误读为行动路线；
- 备选视觉用沿同一组 fan-out Bézier 曲线稀疏分布的柔和珠点，珠点疏密不编码速度或时间，只表达当前材料映射到了哪些地点；
- 原型使用随容器尺寸重绘的 Canvas；生产在 MapLibre GL JS 4.7.x 中将经审校的曲线采样为 GeoJSON `LineString`，由独立 line layer 绘制。原始锚点、控制点、语义和来源必须保留，不能只存屏幕像素；
- 曲线样式必须按 `semantic` 分层，图例明确区分「材料关联 / 影响 / 真实移动」；
- 不确定地点以范围或候选点表达，不把模糊记载伪装成精确坐标；
- 地图浮窗只显示当前 Scene 所需摘要、来源与定位依据。

### 18.3 Scene 地图契约

每个可播放 Scene 至少需要：

```text
scene_id
time { year, month?, day?, precision }
locations[] { place_id, role, certainty, source_ref }
routes[] { from, to, geometry, semantic, certainty, source_ref }
people[] { person_id, place_id?, role }
camera { center?, bounds?, zoom, bearing, pitch, duration }
```

其中：

- `semantic=movement` 才表示真实移动；
- `semantic=influence` 表示影响关系，不应画成行军箭头；
- 缺 `source_ref` 的路线不能进入事实播放；
- 缺可靠地点的 Scene 仍可播放时间与论证，但地图保持上一个有效范围，并明确「本场景无可靠地点」。

### 18.4 镜头与性能

- 默认使用 `fitBounds`，避免为每条事件手写中心点；
- 场景切换只更新当前可见 source，不重建 Map 实例；
- 手动拖图、缩放或切换图层时立即暂停自动镜头；
- 预取下一 Scene 的小量几何与图标，不全量加载探索网络；
- `prefers-reduced-motion` 下直接切换视野或显著缩短动画；
- 浏览器尺寸变化后重新计算标签密度与浮窗位置，不使用固定像素坐标。
- 关联曲线只在容器尺寸、地点集合、选中 Scene 或视觉方案变化时重算；少量可见关系保持 O(可见边)，不运行常驻逐帧动画。

## 19. 原型状态矩阵

原型不只展示理想完成态，必须能切换以下状态供开发核对：

| 模块 | 正常 | 加载 | 空 | 错误 / 受限 | 不确定 |
|---|---|---|---|---|---|
| 研究约定 / 论证链 | 骨架可选、证据可查 | 正在建骨架 / 链接来源 | 尚无节点 | 来源失败，可保留已完成部分 | 关系待用户确认 |
| 页内播放 | 地图、时间、人物同步 | 下一 Scene 预取 | 无可播放 Scene | 地图失败，时间与详情仍可用 | 当前 Scene 无可靠地点 |
| 内置阅读器 | 章节与选区可用 | 解析目录 / 建索引 | 未导入书籍 | 文件损坏 / 无文本层 | 页码与版本不一致 |
| 网页来源 | 可预览并外部打开 | 正在载入 | 未填写 URL | 需登录 / 禁止内嵌 / 网络失败 | 页面可见但选区不可读取 |
| 书籍地图 | 地点与选区联动 | 正在解析地名 | 本段无地点 | 地图资源失败 | 同名地点待选择 |
| 关系透镜 | 互证 / 补充 / 冲突按材料出现 | 正在核对来源 | 尚无外部材料 | 来源不可达 | 关系分类待确认 |

原型中的状态入口只存在于对应区域的完整产品旁注中；生产界面不常驻「状态演示」工具。评审状态必须局部、可恢复并保留最近可用内容：

- W03：`ready / partial / no_location / tile_error`；
- P04：`paused / playing / buffering / ended`；
- B01：`reader_ready / web_limited / login_required`。

这些不是三个孤立枚举，而是五层状态模型的局部投影：探索生命周期、页内能力、区域资源、认识论状态和用户交互各自独立，不再由一个 `demo` 字段包办。

## 21. v5：从「可演示工作台」到「可复用拆书工作流」

> 状态：**空状态、Prompt 范围合同、TXT / Markdown / EPUB 私人解析、连续阅读进度与微信读书手动桥接已进入生产代码；真实 LLM、持久化、外部检索、PDF / OCR 与公开发布尚未接入**

v4 证明了阅读、论证链、地图 Scene、播放和证据可以共享一个 Exploration。v5 不再增加页面，而是补上这套工作台背后的可复用生产流程：任何历史问题或私人书籍都要经过同一组范围、来源、认识论与人工复核闸门，才能进入时空装置。

完整执行规范见：

- [`docs/workflows/book-to-exploration.md`](./workflows/book-to-exploration.md)
- [`docs/workflows/book-to-exploration.schema.json`](./workflows/book-to-exploration.schema.json)
- [`docs/workflows/book-to-exploration.private-validation.json`](./workflows/book-to-exploration.private-validation.json)

### 21.1 v5 的单一流水线

```text
空白
  → Prompt 或私人书籍
  → 研究范围确认
  → 章节 / 段落或来源记录
  → 作者论点
  → 事实候选
  → 时间 / 地点 / 人物
  → Scene / 证据关系
  → 反证与证据缺口
  → 人工复核
  → 私人探索 / 可公开衍生分析
```

Prompt 没有书，范围确认后按研究子问题建立 `source_packets`：每个来源包说明目的、来源和锚点，不能伪造章节。书籍路径必须先得到真实目录、spine 和段落定位，再做内容分析，且不能混入 `source_packets`。`input.mode=prompt / book` 两条分支互斥；空状态使用 `mode=none`。两条路径只在「可回到来源的锚点」处汇合。

研究范围新增 `allowed_source_sets`，由用户明确允许本轮使用原书、平台知识库、用户外部材料和公开外部材料中的哪些集合。Prompt 本身不是来源材料：`model_send_policy` 只约束书籍片段和外部来源；Prompt 是否在用户触发模型时发送，由 `prompt_send_policy` 单独记录。

生命周期也进入合同：空白 / 输入 / 范围草案只能使用 draft scope；从 `scope_confirmed` 起必须有 confirmed scope、非空问题和允许来源集合；Prompt 或书籍推进到 `structure_indexed` 后必须分别具有来源包或章节。

### 21.2 四种来源角色是硬边界

| 角色 | 产品含义 | 最低证据 | 默认状态 |
|---|---|---|---|
| 原文陈述 | 指定材料明确写出的内容 | 原文锚点 | 单一来源，待核 |
| 作者判断 | 作者的解释、评价、因果框架 | 作者主体 + 原文锚点 | 作者判断，不升格事实 |
| 平台推断 | 平台从多个材料提出的结构 | 被推导 Claim | 模型推断，待用户接受 |
| 外部证据 | 原书之外的史料或研究 | 独立来源 + 定位 + 权利状态 | 单独来源层 |

系统不为页面完整而补「正反」：只有同一个 Claim 存在不可同时成立的材料时才显示直接冲突；方法不同、范围不同和观察层级不同分别表达。没有找到反证时显示证据缺口，不生成占位反方。

### 21.3 私人原书与公开产品

私人 EPUB / PDF / TXT：

- 原文件不进入 Git、日志、数据库或公开导出；
- 当前私人运行态会把解析后的段落放进仅属于上传者、6 小时失效的进程内 Snapshot，供内置阅读器使用；进程重启即清除；
- 可版本化 workflow artifact 只保存 locator 和衍生结构，不复制正文；
- 当前未接模型；未来模型只接收用户确认的片段；
- 私人探索可以保存衍生摘要、结构和定位引用；
- 用户持有文件不等于平台获得公开再分发权。

公开候选默认只包含书目元数据、平台原创且不可重构原书的分析、经复核的历史结构、合法公开来源和权利已审查的短引文。原文件、连续正文、长引文、私有路径、Cookie、全文索引和可顺序重构原书的章节摘要必须排除。

公开投影必须同时通过：

```text
无原文文件
无私有 locator / 路径
无凭据
无可重构原书的连续摘要
外部材料权利已记录
人工批准
```

每项发布检查使用 `pass / fail / unknown / not_applicable`，不再以 false 混淆「检查失败」和「尚未检查」。只有六项全部为 `pass` 才能进入 `derivative_ready`；其余状态只能保留为私人探索或阻塞。

### 21.4 微信读书与外部网页不是数据接口

现行状态拆为：

- `external_open_only`：微信读书在 Chrome 顶层打开并保持第一方登录；
- `companion_capture_ready`：扩展已安装，但尚未读取任何内容；
- `companion_preview`：用户主动读取了当前选区，只在 Side Panel 内存中预览；
- `companion_synced`：用户二次确认后写入当前 Exploration revision；
- `manual_progress_bridge`：无扩展时，用户手动确认章节、百分比与可选摘录；
- `no_workspace / local_only / failed`：分别表示没有工作区、公开示例仅临时联动、真实写入失败。

跨站 iframe 已退出产品路径。扩展不接管登录凭据，不读取 Cookie、书架或后台全文；content script 只有接到本扩展 Side Panel 的显式捕获请求才返回当前选区。消息协议校验父窗口、精确扩展 origin、版本、ID、微信读书 HTTPS URL 与字段上限；同 ID 重放在当前页面会话内不产生第二次 mutation。手动位置桥仍默认折叠，不声称实时同步，也不把模糊章节名自动绑定到精确段落。

### 21.5 私有 EPUB 结构验证结论

本轮用本机《红太阳是怎样升起的：延安整风运动的来龙去脉》EPUB 做只读验证：

- 包内识别书名、作者高华、语言 `zh`；
- 生产 EPUB 解析器实际得到 28 个含正文的 spine section、4,445 个段落锚点、541,066 个正文字符；单次解析约 85 ms，当前完整私人 Snapshot 约 2.79 MB；
- 45 个 spine 项、15 个正文章节、76 个目录小节；
- workflow 的目录聚合口径统计为 30 个内容单元、487,694 个去空白可见字符、3,428 个段落标签；它与运行时 spine section / paragraph 口径不同，不应混为同一个计数；
- 已形成逐章统计，并以章节级 locator 提议权力重组、解释权、组织 / 教育技术、审干与抢救、1945 年制度化收束五条作者论证主线；
- 已形成 5 个 `author_judgment`、1 个 `platform_inference`、5 个待核事实候选、5 个待核 Scene 与 9 个显式缺口；
- 所有分析都是不含原文的原创摘要，统一 `pending_review`；平台五段编排明确不是作者明示模型；
- 没有把文件路径、文件 UUID、正文、长引文或段落内容写入仓库；
- 包内日期没有被冒充为可核验纸书版次。

这验证了合同可承载真实长书的「结构 → 作者论证候选 → 时空 Scene → 证据缺口」。私人 EPUB 解析与连续阅读已经上线为首个本地会话切片，但深度分析仍是经人工检查的离线 Demo；任何作者判断、事实候选或 Scene 都没有被采纳为历史事实。由于仍缺 CFI、独立外证和反证检索，它不能进入 `evidence_audited` 或公开衍生状态。

### 21.6 v5 开发闸门

后续实现继续以 workflow 的 Acceptance Matrix 为闸门：

1. 空状态不泄露示范书；
2. Prompt / book 输入字段互斥；
3. Prompt 路径不编造章节，进入结构态后至少有一个来源包；
4. 书籍路径不混入 Prompt 来源包；
5. 生命周期、scope 状态和允许来源集合一致；
6. EPUB 原文件与正文不进入分析 JSON；
7. 四种来源角色不能互相冒充；
8. 无锚点不生成作者判断；
9. 地点歧义不上精确地图；
10. 没有冲突材料时不生成反方；
11. gap 的 target type 与实际对象集合一致；
12. 中断后保留已完成阶段；
13. 微信读书受限状态诚实可恢复；
14. 发布检查的 unknown / not applicable 不得冒充通过；
15. 任一发布检查不是 pass 都阻止公开投影；
16. JSON Schema 与跨 ID 引用校验通过；
17. 人工复核只作用于探索层，不直接改正式知识库。

### 21.7 《安史之乱》公开受限 Demo

公开示例改用《安史之乱：历史、宣传与神话》。本机 EPUB 只用于只读结构分析和工作流前向验证，不进入 Git、浏览器公开状态、日志或构建产物。公开产品采用“全链路、有限原文”的双层证据视界：

- 公开层保留 9 个 Scene、9 个稳定公开锚点、原创衍生摘要、分析框架、已核地点、证据关系与播放次序；
- 私有层保留原书容器、正文、包内 locator 与解析索引，只对上传者当前会话可见；
- 论证节点可以回到对应公开锚点；锚点在未获权利审查时显示章节级定位和“原文未公开”，而不是失效链接；
- “最多 10 页”是未来逐页审查后的产品窗口上限，不是法律安全线。当前 `publishedPages=0`，浏览器和 Pinia 状态均不接收原文；
- 掩码的实现边界是“数据未下发”，不是 CSS 遮盖。DOM、store、localStorage、网络响应和构建产物都不得出现私有正文、包内 href、哈希或本机路径；
- 潼关—灵宝、河阳—邙山目前缺仓库内可靠地点实体，Scene 明确显示“地点待核”，不继承上一幕高亮，也不猜坐标或伪造行军线。

这套设计使 Demo 可以完整展示“论证 → 定位 → Scene → 时间 → 地图 → 证据 → 播放”，同时把公开原文权利审查留成独立、可逐页推进的门槛。以后若有经审查的短摘录，只需把对应锚点从 `restricted` 晋升为 `excerpt_visible`；不需要重写工作台信息架构。

### 21.8 v10 地图全览、历史参照轴与论证图合同

本轮把《安史之乱》从“逐幕播放器”补成可先看全局、再进入局部的探索装置：

- **地图双镜头**：默认 `overview` 同时投影全部有可靠坐标的 Scene，并用序号和可点击九幕清单表达完整顺序；点地图节点或清单项后进入 `focus`。没有可靠坐标的 Scene 保留在清单中并标记“未定位”，聚焦时清空上一幕地点、材料关系和叙事线。
- **叙事线不冒充路线**：相邻的已定位 Scene 使用采样 Bézier 连续曲线连接，线段属性固定声明 `semantic=narrative_sequence`、`claim=sequence_not_route`。曲线只编码阅读先后，不画箭头、不使用机械直虚线，也不填补跳过的未定位 Scene。
- **纵向双轨参照轴**：左栏时间 tab 占满可用高度，755—763 每年一行。主轨只承载九幕 Scene；参照轨只使用仓库实体已经存在的明确 `date.year`、`end_date.year`、`reign_start.year` 或 `died.year`，当前包括安史之乱起止、马嵬驿之变、唐肃宗/代宗即位、收复两京与王维卒。参照项不是装饰标签，点击会同步现有 `useTimeStore` 和 `useSelectionStore`。
- **六类论证图**：每幕必须区分问题、材料观察、推理机制、行动或转折、后果、限制或不确定性；节点还必须标明 `historical_fact / author_judgment / platform_inference / uncertainty` 之一。边使用 `frames / grounds / explains / triggers / leads_to / qualifies / complicates / contradicts` 等显式语义，`contradicts` 只有在同一命题的冲突材料与 locator 均存在时才允许出现。
- **Prompt 仍是合同，不是调用**：后端 `book_argument_graph.v1` 会把用户问题、来源 locator、请求视图、JSON Schema 和史实边界编成 `needs_model / not_called` 队列项。正文只能在未来获得授权的运行时按 anchor 注入，当前快照和公开 Demo 都不携带私人源文本。
- **去掉伪联动**：研究 Brief 下方原有“结构压力 / 战争动员 / 军政决策 / 联盟政治 / 历史记忆”按钮只改了一个无人消费的 store 字段，已删除；重新出现任何主题筛选前，必须先定义它具体筛选、强调或重编织哪个视图，并补同状态联动验收。

这三组能力共享同一 `selectedSceneId`，但不共享未经验证的语义：时间相邻不自动等于因果，叙事相邻不自动等于移动，作者判断不自动等于平台事实。
