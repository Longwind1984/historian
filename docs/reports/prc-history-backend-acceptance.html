监控记录与反思

来源检索没有被误判成内容缺失

本机 Downloads/Documents 未发现对应文件；微信读书工具因本地技能版本要求升级且下载授权超时，记为“环境未核验”，随后改用出版社官方公开样阅，没有据此宣称书不存在。

外部获取是最大耗时点

9 个小型公开图片资源的浏览器资产打包耗时 2475.2 秒，远高于 OCR 的 11.0 秒 和本地后端的 34.5 ms。采集与 OCR 时长是运行者提供的外部观测值，机器记录另行标注其来源；生产流程必须为每个外部阶段设置独立超时、进度事件和可恢复 checkpoint。

并行审计发生上下文污染

一次复用的审计 Agent 误执行了旧的一次性通知任务。幂等标记阻止了重复外部动作，但本轮审计没有完成；主流程及时移出依赖链。以后必须为跨任务 worker 使用全新、无历史上下文的任务，并校验首个 checkpoint 是否匹配 run_id。

“质量门通过”不代表“内容正确”

零主张、零事件时，引用完整性等门仍可形式上通过，因为没有对象可违反约束。报告因此把 explicit_no_model 视为安全通过，却把内容质量明确标为未运行。

明显缺陷与下一轮实现顺序

来源状态缺失

增加 rendered → ocr_unverified → ocr_reviewed 状态与逐页置信度；低置信字符必须回看图像，不能直接成为事实锚点。

类型路由会误删能力

书目元数据、用户声明与正文信号应共同形成带不确定度的类型先验；出现 close_type_scores 时运行多路 Pass，不应直接跳过论证提取。

P0

单文档模型不足

引入 Series / Volume / Chapter / Page / Passage 层级与跨卷 synthesis；每个洞见必须能回到卷、章、页图与段落锚点。

P0

真实内容验收未运行

在明确的数据出境边界下配置模型通道，建立人工金标：主张归因、作者判断、事件时序、人物同一性、地点解析、反证缺口分别计分。

P1

观测仍不够完整

为采集、OCR、分段、每个 Pass、复核和投影记录开始/结束、输入输出计数、摘要哈希、重试原因与成本；日志不得保存原文。

P1

观点结构不能二元化

固定区分“作者判断 / 书内材料 / 平台推断 / 其他研究”，只在真实冲突存在时建立反方关系，不强行生成正反观点。

结论

《中华人民共和国史》适合作为 history-kb 的长期黄金验收集，尤其适合暴露多卷层级、复杂论证、时空网络与来源归因问题。本轮在强制 NoModel 的范围内证明了控制面不会编造，且能够恢复、复核和删除。 无论控制面结果如何，当前类型路由与来源状态都还不足以承担“真实拆书”的核心承诺。

准入标准：修复多路类型路由与 OCR 状态后，再用合法完整副本运行真实模型金标评测；在作者判断归因、事件时间、引用跳转和跨卷综合均达标前，不将其标为“已支持”的公开 demo。
