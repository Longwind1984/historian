## 0. 本次诊断记录（2026-07-11，方案制定时实测）

以下结论均在运行中的 dev 实例（backend :8000 / frontend :5173）实测得出，未改任何代码：

1. **「谱系星图无法打开」真相 = 前端布局塌缩，不是数据问题。**
   路由能切换、`getGlobalGraph` 正常返回（120 节点/284 边）、Cytoscape 画布已创建——
   但图区高度塌为一条细带：工具条（邻居/路径/全局）、截断警告（"只显示前 200/283 个"）、
   FilterWhere 控件全部叠压在一起，画布 0 高不可见。修复点在 GraphPanel/GraphView 的 flex 布局链
   （`.gv-body` → `.graph-panel` → 画布容器缺 min-height/flex 约束，EntityDetail 面板挤占全部高度）。
2. **数据侧的次要事实**（用户猜测的双链覆盖率方向部分成立，但非"打不开"主因）：
   - 双链覆盖率低：7,011 实体中仅 794 个满足 `min_links≥2` 入图资格（≈11%）；
   - `/api/links/global` **每次请求都全量扫描，冷热一样 2.6s**（NameIndex 建了缓存但 mention 扫描没缓存）。
3. **疆域「无疆域数据」是第二个 P0**：`/api/territories?year=750` 返回 871 个多边形，
   但 MapPanel 的 `paintTerritories` 仍被 `map.isStyleLoaded()` 门禁挡住——底图瓦片被系统代理
   拦截时该条件永不满足 → 疆域永远不绘制（WORKLOG 里声称的修复与当前代码不符，属回归/未修完）。
   叠加问题：CHGIS GeoJSON 的 properties 为空（无 polity_id/name/color），图例即使绘制也无名可显。
4. Schema 底账（为新玩法特性摸底）：
   - Event 已有 `date` + `end_date`（跨 N 年**字段已备**，缺的是数据填充与前端时间带渲染）；
   - Person **没有**身份类型/重要性字段（需 schema 扩展）；
   - 事件↔事件关系类型未注册（relations 自由字符串，需注册 + UI 样式）；
   - 关系卡片已有少量 note（如 CBDB "赠诗、文"），但无表达"关联逻辑"的规范字段要求。

## 1. 现状与短板

v1 事实状态：7,011 实体 / 9,909 关系 / 5,311 人物 / 55 政权 / 34 份疆域 GeoJSON，秦→清 2100 年，
全部 YAML + 出处；FastAPI + 内存索引；Vue3 双视图；2026-07-11 刚完成架构重构（首屏 134KB）。

短板（按痛感排序）：
1. **两个 P0 显示 bug**：星图布局塌缩（§0.1）、疆域不绘制（§0.3）
2. **几乎无测试**——改动无验收闸门（这也是 P0 能溜进主分支的原因）
3. **交互粗糙**（Rick 点名）：时间轴不能 zoom in/out；左右两栏比例不可拖拽调节；只按朝代分段、无帝王世系二级定位
4. **玩法薄**（Rick 点名）：事件不表达跨年跨度；事件之间无关联；人物无身份/重要性维度，无从筛选
5. **内容过简**（Rick 点名）：关系卡片不解释"为什么相关"；人物生平一两句话；无内容规范
6. 性能天花板：5,311 人列表无虚拟滚动；`/links/global` 每请求 2.6s 无缓存
7. README 与现实脱节；Neo4j 是从未验证的死重；vis-timeline 依赖未使用
