# Exploration v4 被打回后的联合审计

> 审计日期：2026-07-26
> 目标：判断现有原型是否足以让 Product Manager 在一场发布会中，从产品定位讲到页面排布、状态、边界与开发批准。
> 证据：本轮重新捕捉的 `01-current-weave.png`、`03-current-annotation-regular.png`、`04-current-play.png`、`05-current-book.png`，以及对应 DOM 与 `App.jsx`。

## 1. 用户目标与可访问性目标

评审者应该不依赖旧对话，仅通过原型和 Presenter 讲解就能回答：

1. 这不是“多一个聊天框”，而是什么新产品；
2. 编织、播放、书籍为什么是同一探索的三种工作状态；
3. 每块区域为何占据这个位置和比例；
4. 正常、生成、部分可用、不确定、失败、受限时分别发生什么；
5. 哪些判断已经进入数据合同，哪些仍是视觉假设；
6. 为什么现在可以或不可以批准进入生产开发。

可访问性目标不是证明 WCAG 合规，而是确保讲解不只依赖颜色、聚光动画或鼠标：章节、焦点区域、当前步骤、状态和恢复动作都要有可读文本、语义顺序和键盘路径。

## 2. 有价值的基础

- 三态已经形成不同的视觉重心：编织重在范围与结构，播放重在地图与节奏，书籍重在原文与论证。
- 地图不是装饰：三个模式都尝试让时间、地点、当前命题与证据同屏。
- 证据关系已拒绝固定正反栏，方向判断正确。
- 米白纸感、赭红、宋体与正式产品相容，可以继续作为视觉基线。

这些是可保留的素材，不足以构成可批准的产品。

## 3. 四步体验审计

### Step 1：进入编织态 — 不健康

画面直接展示“范围已确认”和一张完成度很高的地图，但没有讲清：

- 用户为什么需要从静态知识库进入探索；
- 一次探索的交付物究竟是回答、路径、网络还是研究版本；
- 为什么左侧是对话、中央是地图、右侧是证据；
- 范围确认之前、生成中和部分可用时会看见什么。

风险：评审者看到的是功能拼盘，不是产品承诺。

### Step 2：点击 W03 标注 — 不健康

标注面板逐项列出“定位、默认、交互、状态、数据、验收”，但每项只有一句定义。它像组件需求表，不像 Product Manager 的讲解：

- 没有先提出地图解决的用户问题；
- 没有解释为何地图居中、为何占最大面积；
- 没有用当前靖难场景证明地图如何改变理解；
- 没有展示无地点、模糊地点、瓦片失败时的实际画面；
- 没有讲出选择 MapLibre 而不是静态图的生产 tradeoff。

风险：字段看似完整，实际没有形成因果论证。

### Step 3：进入播放态 — 部分健康

地图、场景轨、解释透镜和时间带的空间关系清楚；但当前没有一条“从问题到答案”的发布叙事。代码还暴露出：

- 速度选择没有进入播放计时器；
- 播放结束没有清楚的重播合同；
- 无地点 Scene 仍可能沿用上一地点作为主标题；
- 场景、人物、证据和地图不是从同一共享 Snapshot 读取。

风险：能播放不等于能解释，视觉同步也不等于数据一致。

### Step 4：进入书籍态 — 不健康

书籍态自身的阅读—结构—地图—证据链路有价值，但它与前两态不是同一个 Exploration：题目从靖难之役换成《红太阳是怎样升起的》。模式切换会卸载子组件并重置局部状态。

风险：原型最核心的“三态共享同一研究草案”承诺没有兑现。它实际上是两个样例、三张页面。

## 4. UX 风险

1. **定位没有进入界面。** 用户看不到“从静态知识库到动态研究装置”的转变。
2. **三态不是一个对象的三个视角。** 这是产品结构错误，不是文案问题。
3. **状态演示是假状态。** 顶部 Normal / Loading / Empty / Error 只切换全屏蒙层；“返回正常状态”绕过真实恢复。
4. **静态成功标签透支信任。** “范围已确认、自动保存、已导入、史实已核验、无实质冲突”都没有运行条件。
5. **标注没有叙事顺序。** 评审者必须自己随机点编号拼出产品逻辑。
6. **未定义批准条件。** 原型没有告诉评审者当前讲到了哪里、还缺什么、批准后开发什么。

## 5. 可访问性风险

- 标注编号依赖小型浮标和视觉位置，缺少一条线性的可读讲解目录。
- Presenter 若只用遮罩和聚光，键盘用户与读屏用户会失去上下文；下一版必须同步更新章节标题、当前区域和步骤进度。
- 播放自动推进需要暂停原因、`aria-live` 更新策略和减少动态选项，截图无法证明这些已经实现。
- 当前 1440 桌面布局在窄 Codex 浏览器默认视口会水平裁切；这不是本轮的移动设计范围，但 Presenter 必须明确主验收视口并在窄视口给出受支持提示。

## 6. 机会与重做方向

下一版不是“给每个标注多写几段话”，而要加入一套 Presenter Mode：

1. 先给出产品命题和用户改变；
2. 按固定章节带观众走过一个共享 Exploration；
3. 每步只聚焦一个区域，同时讲“问题—设计—现场效果—状态—tradeoff—开发合同”；
4. 在当前区域内现场切换部分可用、无地点、证据缺口、来源受限等真实局部状态；
5. 允许随时退出讲解自由探索，并能返回原步骤；
6. 最后一章自动汇总已证明、待证明和生产批准清单。

## 7. 当前结论

上一版视觉骨架可作为素材保留，但产品验收失败。只有当以下三件事同时成立，才能重新标记开发就绪：

- 一个共享 Exploration Snapshot 真实贯穿三态；
- 状态从全屏演示蒙层改为分层、局部、可恢复的业务合同；
- Presenter Mode 能把每个页面判断讲成一条可跟随、可复现、可批准的发布叙事。
