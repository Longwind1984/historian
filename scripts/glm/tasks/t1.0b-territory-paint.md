# 任务：修复地图疆域不绘制（P0）

## 目标
时间柱视图右侧地图在任何年份都能绘制疆域多边形并显示图例——**即使底图瓦片全部加载失败**（用户环境有系统代理 127.0.0.1:7897 拦截外网瓦片请求，这是常态而非异常）。
当前症状（2026-07-11 实测）：`GET /api/territories?year=750` 返回 871 个 feature，但地图区域空白、图例位置显示「无疆域数据」；console 里 maplibre 瓦片请求 Failed to fetch 刷屏。

## 已知根因（已诊断，直接修）
`frontend/src/components/map/MapPanel.vue`：
1. 第 115-123 行：疆域绘制入口有两个——`map.on('load')` 与 `map.on('styledata')`。后者被 `if (map.isStyleLoaded())` 门禁包住；当瓦片持续加载失败时，MapLibre 的 `isStyleLoaded()` 可能永远不返回 true，`load` 事件同样可能不触发 → `paintTerritories` 一次都不执行。历史 WORKLOG 声称"改为 styledata 事件后直接绘制"，但当前代码的门禁仍在，属未修完/回归。
2. 次要问题：第 153-162 行图例从 `f.properties.polity_id / polity_name / polity_color` 构建，而 CHGIS 导出的 GeoJSON properties 为空 → 即使绘制成功，图例也会是一行 undefined。本任务只需**容错**（properties 缺失时图例显示"疆域 N 块（政权信息待补）"之类的降级文案，不显示 undefined）；properties 数据补全是后续 T2.4 的事，不在本任务范围。

## 修复要求
- 疆域绘制不得依赖瓦片就绪：style 的 JSON 解析完成后即可 addSource/addLayer（可用一次性 styledata + 防重入标志、或 `map.once('style.load')`、或轮询 `map.getStyle()` 可用性，任选最稳妥方案）；同时保留年份变化时的重绘逻辑（找到现有 watch 确认它走的路径同样不被门禁挡住）
- 加一层兜底：若首次绘制因 style 未就绪抛错，应重试而不是静默放弃
- 瓦片请求失败允许发生，但不应导致疆域/图例功能异常，也不应让 console 无限重试刷屏（若 MapLibre 有失败重试控制项则配置之；没有则至少不因我们的代码放大）

## 边界（硬约束）
- 只允许修改：`frontend/src/components/map/MapPanel.vue`（如确需，`frontend/src/styles/**` 可小改）
- 不新增第三方依赖；不改后端；不改 `scripts/glm/**`、`docs/**`
- 不执行 git commit / push
- 不改底图源列表本身（T2.5 的事）
