# 任务：数据校验器 scripts/validate_data.py（T1.2）

## 目标
一条命令对 `data/**` 全量数据做结构与引用完整性校验，输出人类可读报告 + 机器可读退出码。它是后续所有数据批量任务（M4 重扫/扩容）的强制闸门。

## 校验规则（按严重度分级）
**ERROR（存在即退出码 1）**
- YAML 解析失败 / 缺 `id` / 缺 `type` / `type` 不在 schema 注册表中
- id 重复
- 实体缺 schema 中 `required: true` 的字段（读 `schema/*.yaml` 动态判定，不硬编码）
- 关系（`data/relations/*.yaml`）两端 id 在实体集中不存在
- 年份逻辑硬伤：born>died、政权 founded>fell、关系 since>until、事件 date>end_date

**WARN（计数与清单，不影响退出码）**
- 实体缺 `sources` 或 sources 为空（按类型统计缺失率）
- 关系缺 `note`（语义说明）——为 M4 内容规范预热，先只统计
- 孤儿实体：不出现在任何关系两端、且正文（bio/description）也不被任何其他实体的双链提及（复用 backend/app/api/links.py 的 NameIndex 思路或简化实现，避免 O(N²) 全暴力：先建 name→id 索引再单遍扫描）
- Person 无 born 或 died；Event 属 coup/reform/war 类却无 impact
- GeoJSON 检查：`data/geo/*.geojson` 可解析、features 的 properties 是否含 polity_id/polity_name（统计缺失文件清单——已知 CHGIS 文件全缺，作为基线记录）

## 输出
- stdout：分级汇总（ERROR 明细逐条；WARN 按类别计数 + 前 10 例）+ 末尾一行总览 `entities=N relations=N errors=N warnings=N`
- `--json <path>` 可选参数：完整机器可读结果落盘
- 运行时间：全量 7000+ 实体应 <30s（单进程纯 Python 即可，注意别写 O(N²)）

## 边界（硬约束）

- 允许小改：无
- **不得修改任何 data/ 下的数据文件**——发现的数据问题全部进报告，不修
