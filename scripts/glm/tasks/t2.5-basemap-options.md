## 实现备注（Claude 规划，2026-07-11，工人按此实现；已读源码确认）

### 关键现状（已确认，勿重复踩坑）
- `MapPanel.vue:246` `map.addLayer({...territory-fill...}, 'basemap-tiles')`：第 3 参是 `beforeId`，语义=「插到该层**前面**(更靠下)」，故 fill 实际在瓦片**之下**。行内注释「叠在底图之上」写反了。**修法：删掉 `, 'basemap-tiles'`**，fill 追加到顶层(瓦片之上)；border 本就无 beforeId(追加顶层，在 fill 之上)。最终底→顶：bg → basemap-tiles → territory-fill → territory-border。
- **`territory-label` 层并不存在**（仅在 `:222` 清理数组出现，从未 addLayer）。任务里 label 是 stale，**不要新建 label 层**；清理数组里的引用留着无害。
- maplibre-gl **4.7.0**。
- `useUIStore` 有 `basemap`/`setBasemap` 但 MapPanel 用本地 ref——**保持本地 ref**，不要接入 store（超范围）。
- 纸色：`applyPalette()` 把 `--paper` 注入 `:root`（澄 `#f2ebdd` / 夜 `#12181f` 等，随主题变）。素底 bg 读这个变量。
- **console 静音原理已验证**：maplibre 全 bundle 仅 1 处 `console.error(t.error)`，是 Evented 在「error 事件无监听」时的兜底。**挂上 `map.on('error', ...)` 即不再 console 报错**。且本应用里唯一网络错误源就是瓦片（territories/graticule 都是本地 geojson）——故「非素底图期间，任何 error 事件 = 瓦片错误」，**无需解析 sourceId**。

### 「素」底图——统一 source 方案（不要 setStyle，会清掉疆域层）
所有底图共用同一份 style 骨架，素底只是「瓦片源 tiles 置空 + 网格层可见」：
- `buildStyle(id)` 始终返回 sources `{ basemap:{type:'raster', tiles:bm.tiles, tileSize:256, attribution:bm.attribution, maxzoom:bm.maxzoom}, graticule:{type:'geojson', data:GRATICULE_FC} }`，layers `[ bg, basemap-tiles(raster,source:basemap), graticule(line,source:graticule) ]`。
- `BASEMAPS.素 = { id:'素', label:'素底 · 本地古风', glyph:'素', type:'raster', tiles:[], attribution:'', maxzoom:10 }`（tiles 空数组=不请求，与退避复用同一路径）。
- bg：`'background-color': readPaper()`，`readPaper()` = `getComputedStyle(document.documentElement).getPropertyValue('--paper').trim() || '#f2ebdd'`。
- graticule 层 `layout.visibility`：`id==='素'?'visible':'none'`；paint：`line-color` 读 `getComputedStyle(...).getPropertyValue('--line').trim()||'#e2d9c6'`，`line-width`:1，`line-opacity`:0.55。
- graticule GeoJSON：模块顶层 `const GRATICULE_FC = buildGraticule()` 生成一次。`buildGraticule()` 返回 FeatureCollection，每 10° 一条 LineString：经线 lng -180..180 step10 → `[[lng,-90],[lng,90]]`；纬线 lat -80..80 step10 → `[[-180,lat],[180,lat]]`。约 54 条，纯代码，不落静态文件。

### switchBasemap(id) 改写
- `map.getSource('basemap').setTiles(BASEMAPS[id].tiles)`（素→[]，其余→正常 tiles）
- `map.setLayoutProperty('graticule','visibility', id==='素'?'visible':'none')`
- `map.setMaxZoom(BASEMAPS[id].maxzoom)`
- 切到某 id 时重置该 id 错误计数（=一次重试机会）

### 瓦片失败退避
- 状态：`const errCount = Object.create(null)`（按 id 计，非响应式）；`const disabledIds = ref([])`（驱动 UI，用 `.includes/.push`，删除用 reassign filter）。
- `map.on('error', () => { ... })`：`if (basemap.value === '素') return`（素无瓦片）；否则 `errCount[basemap.value] = (errCount[basemap.value]||0)+1`；`>=5` 时 `map.getSource('basemap').setTiles([])` 且 `disabledIds.value = [...disabledIds.value, basemap.value]`（去重）。监听挂上即抑制 console。
- N=5。无法逐瓦片探测成功来重置「连续」计数——以「切换底图=重置」近似，报告中说明此局限。
- UI：`.bm-btn` 加 `:class="{disabled: disabledIds.includes(b.id)}"`、`:title="disabledIds.includes(b.id) ? '瓦片不可达 · 点击重试' : b.label"`。`switchBasemap` 入口逻辑：①`id===basemap.value && disabledIds.includes(id)` → 重试（`errCount[id]=0`；`disabledIds.value=disabledIds.value.filter(x=>x!==id)`；`setTiles(BASEMAPS[id].tiles)`）；②`id===basemap.value`（未 disabled）→ return；③否则正常切。
- CSS：`.bm-btn.disabled{opacity:.4;cursor:not-allowed} .bm-btn.disabled:hover{background:transparent}`。5 个 30px 按钮+gap3px ≈168px，左上角不碰右上 overlay，无需改尺寸。
