# 任务：实体列表接口字段裁剪（T2.6）

## 侦察结论（Claude 已完成，按此干——勿重复排查）

### 数据形状的关键陷阱（决定 fields 白名单对错）
- **`significance` 在 Person 上不是顶层字段**：它存在 `ext: {significance: ...}` 里。TimeColumn 代码 `p.significance` 对 Person **恒为 undefined**（全 5311 人中 0 人有顶层 significance）。所以 **Person 的 fields 不要带 significance**（带了也按"未知字段忽略"是 no-op，但别误以为它能取到值）。
- **`significance` 在 Battle 上是顶层字段**（sample Battle keys 含 `significance`），且 TimeColumn 的 `e.significance` 对 Battle **真能取到**。所以 **Battle 的 fields 必须带 significance**。
- **`impact` 仅 Event 有，Battle 没有**；`end_date` Event 有、Battle 没有。这些字段对不存在类型按 spec 忽略即可。
- **`ext` 是顶层 dict**（含 significance 等）。TimeColumn 不消费 ext 块，**不要请求 `ext`**。
- Person 默认响应顶层 keys（sample）：`alias, bio, birthplace, born, died, gender, id, name, sources, type`（部分人还有 `courtesy_name/image/ext`；CBDB 扩展人还有 `dynasty_ref/name_en`）。
- Event 顶层 keys：`category, date, description, end_date, id, image, impact, location, name, polities_involved, sources, type`。
- Battle 顶层 keys：`combatants, commanders, date, description, id, location, name, significance, sources, type, victor, victor_commander`。

### 字节数基线（Claude 已在真实数据上量得，供你交叉验证）
- `GET /api/entities?type=Person&limit=2000`（无 fields）= **505,225 字节**（2000 项 / total 5311）
- 投影（fields=`id,name,born,died,bio,image,courtesy_name`）= **229,163 字节** → 降幅 **54.6%**，达 ≥50% 目标（有 4.6pt 余量）。
- Event limit=500：60,892 → 45,519（25.2%）；Battle limit=500：19,221 → 12,576（34.6%）。这两路不是验收硬指标，但顺带降。
- FastAPI 响应序列化 = `ensure_ascii=False` + 紧凑分隔符 `(",", ":")`（无空格）。量字节用 `len(r.content)`（真实响应）即可，别用带空格的 `json.dumps`。

### 后端实现要点（已确认边界）
- `backend/app/api/entities.py`：`list_entities_api` 加 `fields: str | None = Query(None, ...)`；给定时 `fields_list = [f.strip() for f in fields.split(",") if f.strip()]`，传给 `list_entities(..., fields=fields_list)`。
- `backend/app/services/entity_service.py`：`list_entities` 加 `fields: list[str] | None = None` 形参；新增正交小工具 `_pick_fields(items, fields)`：`fields` 为 None/空时原样返回（**合同不变**），否则 `allowed = set(fields) | {"id","type"}`，`[{k:v for k,v in it.items() if k in allowed} for it in items]`。
  - **两个 return 分支都要过滤**：(1) `type==Person and year` 走 `load_persons_alive` 的快路径分支；(2) 通用分支。两路 `items` 都要过 `_pick_fields`。
  - **`_serialize` 不要动**——`get_entity`（详情）和 `get_neighbors` 也用它，详情接口不许变。过滤只在 `list_entities` 内、`_serialize` 之后做。
  - 未知字段名天然被忽略（`k in allowed` 匹配不到任何 key 即不出现），不报错——这正是 spec 要求，无需额外校验。
