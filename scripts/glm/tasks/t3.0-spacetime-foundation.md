## B. 新端点 `GET /api/graph/spacetime`
加在 `backend/app/api/graph.py` + service 层，返回：
```json
{ "meta": {"total": N, "with_geo": N1, "with_time": N2, "dynasty_coverage": {...}},
  "dynasties": [{"id","name","from","to"}],   // 全部朝代实体,按 founded 排序(含新增6个)
  "nodes": [{"id","name","type","born","died","x","y","dynasty","links"}] }
```
- **覆盖全部实体类型**：Person（born/died.year；x/y=籍贯 birthplace→Place 坐标）、Event/Battle（born=date.year, died=end_date.year||date.year；x/y=location→Place）、Polity（founded/fell；x/y=capital→Place，字段名先 grep 确认）、Faction/Place 酌情（Place 自身有坐标则给，无时间）
- **先侦察 Place 坐标字段**（读几个 data/entities/places/*.yaml，确认是 lat/lng 还是 x/y 还是 location 嵌套），报告里写明与覆盖率
- `dynasty`：按年份归属朝代（复用/参考 links.py 的 `_dynasty_index` 归属逻辑，但以实体自身年份计算；无年份→null）
- `links`：出链+入链度（复用 links.py 的 MentionGraph 缓存 `_ensure_graph()`，**禁止重扫**）
- 无坐标 → x/y 为 null（前端排雾环）；无时间 → born/died null
- 结果按 `_data_sig()` 进程内缓存；响应用 fields 精简，别把 bio 之类带上
- pytest 合同测试 1 条：200/meta 字段/nodes 数 >5000/李白节点有 born=701 且 dynasty 为唐
