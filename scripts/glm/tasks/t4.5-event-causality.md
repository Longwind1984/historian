# 任务：事件因果关联「前因→本事件→后果」（T4.5，Rick 点名）

Rick 反馈：事件之间应有关联、卡片要表达"关联的逻辑"。现在事件是孤立的。做事件因果链 + 详情卡呈现。

## A. schema/relations.yaml 注册事件↔事件关系类型
读现有 relations.yaml 写法，注册 4 类（若已有则复用）：
- `caused_by`：本事件的前因（A caused_by B = B 是 A 的原因）
- `led_to`：本事件导致的后果（A led_to C = A 导致 C）
- `part_of`：从属于更大事件/时期
- `concurrent_with`：同期并发（无向）
给每类配 UI 样式提示字段（若 schema 有 color/label 惯例，照加）

## B. 数据：为重大事件补因果链（data/relations/，新建 event_causal.yaml）
- 选 ~20-30 组有明确史学因果共识的事件对，写 `caused_by`/`led_to` 关系，**每条带 note（一句因果逻辑）+ sources（正史/公认史论）**。示例（务必核对 id 真实存在，用 grep 确认）：
  - 安史之乱 `led_to` 藩镇割据（note："乱后诸镇拥兵自重,唐廷失控"；source：新唐书·方镇表）
  - 藩镇割据 `led_to` 黄巢起义 / 唐亡
  - 王安石变法 `led_to` 新旧党争（note："变法派与反对派党争贯穿北宋后期"）
  - 靖康之变 `caused_by` 联金灭辽（note："宋金海上之盟灭辽,失屏障致金南下"）+ `led_to` 北宋亡/南宋建
  - 安史之乱 `caused_by` 节度使权重 / 玄宗怠政（若有对应事件/概念实体）
  - 形成几条可追的因果链（安史之乱→藩镇割据→黄巢起义→唐亡）
- **只连真实存在的事件实体**（grep 确认 id）；找不到对端实体的因果暂不连、报告列出
- note 与 sources 必填，缺依据的不硬连

## C. 前端：详情卡呈现因果链
- `EntityDetail.vue`（三视图共用）+ `MomentPanel.vue`（时间柱档案卡）：当实体是 Event 时，增「前因 → 本事件 → 后果」区块：
  - 前因 = incoming caused_by + 指向本事件的 led_to；后果 = outgoing led_to + 指向本事件的 caused_by
  - 每条显示对端事件名 + note（因果逻辑），点击导航到该事件（onNavigate）
  - 数据来源：现有 neighbors/relations API（`/api/entities/{id}/neighbors` 或关系查询）——先确认能拿到关系 type 与 note；拿不到 note 则显示关系类型标签
  - 视觉纸墨克制：前因用"←"、后果用"→"，一句 note 跟随；无因果数据的事件不显示该区块（不留空壳）
