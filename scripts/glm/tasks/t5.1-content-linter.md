# 任务：校验器升级为内容规范 linter（T5.1）

依据 `docs/content-spec.md`。把 `scripts/validate_data.py` 升级：在现有 ERROR/WARN 基础上，增加内容规范合规检查，并提供一个可作为重扫闸门的严格模式。

## 新增检查（在 validate_data.py 内，不破坏现有 ERROR/WARN）
1. **关系关联逻辑**（WARN + 计数）：
   - 语义关系（非亲属类型：排除 father_of/mother_of/spouse_of/sibling_of/child_of）无 note → WARN
   - 有 note 但命中模板套话模式（复用 audit_content.py 的套话正则：致书Y/赠诗、文/答Y书/书跋序由Y所作/为Y作墓志铭 等）→ WARN 计数
2. **人物生平**（WARN）：importance ∈ {1,2} 的人物无 `life_events` 字段 → WARN；bio 为 CBDB 桩（bio 以 'CBDB ID' 开头或等于占位）单独计数
3. **事件**（WARN）：category ∈ {coup,reform} 且既无 impact 又不出现在任何 caused_by/led_to 关系 → WARN
4. **出处格式**（WARN）：sources 项无 '·' 且非纯来源标识（CBDB/CHGIS）→ 疑似不规范，计数

## 严格模式（重扫闸门）
- 新增 `--strict-seed` 标志：把「**种子文件**（data/relations/ 下**非 cbdb.yaml** 的文件）里的语义关系无 note」升级为 **ERROR**（exit 1）。用途：T5.3 补完种子关系 note 后，`validate_data.py --strict-seed` 应为 0 error，作为该批闸门。
- 不加 --strict-seed 时行为 = 现状 + 上述 WARN（默认不因内容规范失败，避免卡住 CBDB 存量）

## 输出
- 现有报告末尾增「内容规范合规」区块：各项 WARN 计数 + 合规率
- `--strict-seed` 下把种子无 note 关系逐条列 ERROR
