# 任务：内容规范合规度盘点（T5.2，只读盘点不改数据）

依据 `docs/content-spec.md`（草案）。本任务**只测量现状与规范的差距**，产出一份基线报告，给 Rick 的规范决策与后续重扫工程量估算提供数字。**不改任何数据、不做重扫。**

## 产出：scripts/audit_content.py（新建，只读）
对全量数据统计并打印分类报告：

1. **关系关联逻辑**：
   - 语义关系（非亲属 father_of/mother_of/spouse_of/sibling_of/child_of 之外的类型）中，无 note 的数量与占比
   - 有 note 但疑似模板化套话的数量（如 note 命中 "收到.*赠诗"、"有交往" 等模式；给出命中的模式清单与计数）
   - 按关系 type 分组：各 type 的总数 / 有实质 note 数
2. **人物生平**：
   - 有 bio 的人数 / bio 过短（<30 字）人数 / 无 bio 人数
   - 有 life_events 字段的人数（现应为 0，确认基线）
   - 按 importance 分层统计（1/2/3/无标注 各多少人、其 bio 覆盖）
3. **各类型字段完整度**（对 content-spec §3 的必填项）：
   - Person：born/died/birthplace/sources 缺失率；核心+重要人物 roles/importance 缺失
   - Event：date/category/description/sources 缺失率；战乱变法类(category in coup/reform/war/rebellion?) 有无 impact 与因果关联
   - Battle：date/location/combatants/结果/sources 缺失
   - Polity/Faction：关键字段缺失
4. **出处格式**：sources 疑似不规范的（无"·"分卷、纯"CBDB"、空）计数
5. **重扫工程量估算**：按 content-spec §6 方案 A（种子全量升级 + CBDB 核心圈层），估算需补 note 的关系数、需加 life_events 的人数、需扩容的事件/战役数——给 Rick 一个"这活多大"的量化

## 输出格式
- stdout 分节报告，每节末尾一行小结数字
- 末尾"方案 A 工程量估算"块：需处理的关系/人物/事件条数
- `--json <path>` 可选落盘
