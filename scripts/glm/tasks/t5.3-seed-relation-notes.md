# 任务：种子关系补「关联逻辑」note（T5.3，史实准确第一位）

依据 `docs/content-spec.md` §1。给种子（非 CBDB）语义关系补一句话关联逻辑 note。**这批内容会经 Anthropic workflow 对全部逐条对抗式史实核查，编造/无据的会被打回——务必只写有据的，宁缺毋滥。**

## 范围
- **只处理种子文件**：`data/relations/` 下**除 cbdb.yaml 外**的所有 yaml（qin_han/sui_early_tang/song/late_tang/weijin_nanbeichao/yuan_ming_qing/extensions/agent_extras/all/event_causal 等）
- **只补语义关系**（排除亲属 father_of/mother_of/spouse_of/sibling_of/child_of——这些自明，不补）
- 目标：这些文件里语义关系无 note 的（audit 计 ~235 条）全部补 note；已有 note 的不动（除非是套话，可选升级）

## note 写法要求（每条）
- 一句话说清**关联逻辑**：谁、因何、与谁、发生了什么。具体、可考。
  - 正例：`欧阳修 -[荐举]-> 苏轼`  note:"嘉祐二年欧阳修知贡举,识拔苏轼,叹'当避此人出一头地'"
  - 正例：`王安石 -[对立]-> 司马光` note:"熙宁变法中司马光领旧党力争,新旧党争之核心"
  - 反例（禁止）：'有交往'、'关系密切'、'同朝为官'（无信息量）
- **每条 note 尽量能对应史料**；若该关系的具体史实你不确定，**宁可不补该条**（留空,在报告列出),也不要编造细节
- note 用中文，简洁（一句话，≤40 字为宜）
- 关系 type 若过泛（associated_with）且能判断更具体类型（荐举/唱和/论敌/同僚/姻亲/师承）可一并改 type，但**不确定就别改 type**，只补 note

## 硬红线（对抗核查会抓）
- 禁止编造具体年份、事件、引语——不确定的细节不写
- 人物关系方向要对（谁荐举谁、谁是谁的老师）
- 不确定的整条留空并入报告"存疑未补"清单，不硬凑

## 边界
- 只改 `data/relations/` 下非 cbdb.yaml 文件（补/升级 note；不新增/删除关系、不改 from/to/type 除非上述明确升级）
- 不改 cbdb.yaml（CBDB 批次是后续独立决策）；不改代码；不 git commit/push；不改 WORKLOG.md
- 环境变量用 `env VAR=... cmd`；后端已支持改数据自动失效
